Actual integration APIs on that main: `AgentAdapter.CheckInstallation(ctx, domain.InstallationInput)`, `preflight.MaterializeEnv`/`ResolveCommand`/`CheckLauncher`, and `opencode.NewRuntime`, `Runtime.Adapter`, `Adapter.ReadinessCheck`, `Runtime.Close`. There is no public lease API. Discovery owns a command-scoped Runtime and closes it once; adapters borrow it. ## Goals / Non-Goals

**Goals:** supply exact, attributable choices before workflow authoring; maintain backend/account/configuration boundaries; return useful partial results within a bounded time; make metadata uncertainty and execution limitations machine-readable.

**Non-Goals:** semantic model matching, model ranking, provider selection, inference verification, billing/quota checks, new admission gates, full Kimi protocol migration, generalized backend option forwarding, a persistent model database, or a new HTTP discovery service.

## Decisions

### 1. Separate session-free adapter contract

Introduce a discovery interface in `internal/adapters`, with DTOs in `internal/domain` to avoid parent/concrete adapter import cycles:

```go
type ModelLister interface {
    ListModels(ctx context.Context, input domain.ModelDiscoveryInput) domain.ModelDiscoveryResult
}
```

`ModelDiscoveryInput` contains an immutable effective backend configuration, absolute workspace, captured environment/launch plan, hidden-model policy, and any borrowed command-owned runtime needed by OpenCode. It contains no prompt, run, session state, or sink. Sensitive input has no JSON serialization and is never echoed. Each registered backend must have a lister, including explicit fake/unsupported implementations. Factory construction is side-effect-free; it does not invoke Init/Recover. Keeping this distinct from AgentAdapter prevents a catalog request from allocating a conversation and avoids forcing execution test doubles to simulate unrelated discovery.

`internal/modeldiscovery` resolves targets, invokes only local `CheckInstallation` (stage 1) per target, aggregates lister results, and owns cleanup. Never call orchestrator/workflow two-stage admission preflight: that would independently start/readiness-check services. For OpenCode, the lister alone calls the existing runtime readiness path and snapshot verification after its local check succeeds, using the same command-owned Runtime. Repeated internal ensure calls reuse that owner; they do not acquire a second server. External mode performs no local executable lookup. Expected backend errors are result data, not an early aggregate error. Internal errors become fixed `error` diagnostics. Reuse the preflight launch resolver; don't add a second PATH or interpreter-resolution policy. A failed installation result maps to `not_installed` for missing prerequisites, `unsupported` for incompatible platform/runtime/launcher, or `error` for an unusable configuration/permission failure, retaining sanitized issue codes. Ready/not_required means discovery can proceed, not authenticated or inference-ready. A failure in one target never gates other target discovery.

### 2. CLI and effective target selection

```
agent-debug-squad models --all --json [--workspace DIR]
agent-debug-squad models --backend codex --backend kimi --json
agent-debug-squad models --config squad.yaml [--backend opencode] --json
```

Flags: `--all`, repeatable `--backend`, `--config`, `--workspace`, `--json`, `--include-hidden`, `--timeout` (whole discovery pass, computed default below), and `--backend-timeout` (default 30s). Positive durations are required. `--all` and `--backend` are mutually exclusive. With no config and no selector, default to all real backends: codex/cursor/kimi/opencode/zcode. Fake is selected only explicitly or by configured agents, so a synthetic success cannot hide failure of every real backend. With config and no selector, discover all distinct effective configurations of its agents, regardless of workflow references. With config plus `--all`, also add machine/default targets for real backends not represented. With config plus backend filters, use all matching agent configurations; a requested backend absent from config gets its machine/default target. Judge is not an agent backend and is not listed.

Standalone workspace defaults to cwd. With config, use its workspace; an explicit different workspace is rejected to avoid querying one project and suggesting selections for another. The config itself follows current structural validation but is never submitted or initialized; a workflow block is unnecessary. Snapshot the machine file once per CLI invocation and capture ambient environment once. Agent options override machine defaults using the existing merge rules. Standalone targets use machine/default configuration and the same environment policy an equivalent agent would use, not the interactive shell's full environment. Missing HOME/PATH/auth under that policy is reported with safe configuration guidance; it is not silently repaired. No placeholder startup prompts or dummy agents are persisted.

Deduplicate by backend, absolute workspace, effective executable/runtime, mode/endpoint, effective child environment and other discovery-relevant settings. Exclude agent name, startup prompt, model/reasoning choice and yolo because these do not change the catalog. Do not exclude arbitrary environment entries: wrappers and account/config locations can affect discovery. Compare complete private values in memory, not just unverified hash equality. Different endpoints, profiles, auth contexts or workspaces remain separate. Assign public target IDs as `machine:<backend>` or `agents:<backend>:<names>`, where names are sorted by UTF-8 byte order, individually percent-encoded (only RFC 3986 unreserved bytes remain literal, uppercase hex), then joined with commas. For example, A,B and C become `agents:codex:A%2CB,C`. This is unambiguous even for delimiter-bearing names; never use secret-derived hashes. Retain the original sorted `agents` array. Equivalent target grouping never merges agent sessions.

### 3. JSON and selection schema

All generated_at/retrieved_at/as_of timestamps use RFC 3339 UTC with a Z suffix. Top-level version 1 envelope: `schema_version`, `generated_at`, `status` (`ok`, `partial`, `failed`), and sorted `results`. In --json mode emit exactly one JSON document on stdout, including failure results; stderr carries only concise safe diagnostics. Each result has `target_id`, `backend`, `agents`, `status`, `complete`, `models`, `sources`, `diagnostics`, and `inference_verification: not_checked`. Result statuses: `ok`, `empty`, `partial`, `not_installed`, `not_configured`, `auth_required`, `offline`, `unsupported`, `timeout`, `cancelled`, `error`. `empty` means a successfully parsed, complete list of zero models. A timeout after some pages is `partial` plus a timeout diagnostic; no rows and a timeout is `timeout`. Unknown auth/network failure is `error`, never a guessed authentication diagnosis.

Each source has a stable ID, kind (for example `codex_app_server`, `cursor_cli_text`, `kimi_local_config`, `opencode_provider_api`, `zcode_registry`, `synthetic`), safe operation name, optional observed backend version, UTC `retrieved_at`, scope (`account_catalog`, `configured`, `known_catalog`, `synthetic`), `complete`, `hidden_policy: {requested: visible_only|include_hidden, applied: visible_only|include_hidden|not_supported|unknown}`, and freshness `{state: fresh|stale|unknown, as_of?, cached?}`. Retrieval time means when Squad received data, not when the upstream catalog was updated. Rows reference their source IDs. Missing pagination or truncated sources cannot be marked complete; complete is relative to the declared source scope and hidden-model policy, not the universe of all models. Codex records both requested and applied policy. Other sources use not_supported only when known to lack hidden filtering, otherwise unknown, and do not claim hidden inclusion from the CLI flag alone.

Model fields: exact `model_id` (native model identifier), optional `provider_id`, optional `provider_label`, optional `display_name`, optional `alias`, optional native `catalog_id`; evidence fields `configured` and `connected` are nullable booleans, `listed: true`, and optional source-reported `disabled_reason`/`hidden`/`is_default`. Here configured means exposed by the effective runtime's configured-provider/model representation, not necessarily declared in a user-written file. No source value means null/omission, not false. A display name is not fabricated from brand knowledge; text output may fall back to model_id without populating display_name. Listing/account connection is never successful inference evidence.

Use `not_configured` only when a required context/profile/endpoint is explicitly missing and listing cannot proceed; a supported empty configured model map is `empty`. A recognized authentication-required response becomes `auth_required`; absence of connection evidence alone does not. A confirmed transport/DNS/connectivity failure becomes `offline`, a deadline becomes `timeout`, and an unclassified failure remains `error`. All failure statuses have complete=false. Aggregate status is ok for all complete ok/empty targets, partial if any usable rows or complete empty result coexist with degradation, and failed otherwise. No-target configuration is an exit-2 configuration error rather than vacuous success.

`selection` contains `backend`, an allowlisted `options` map of exact Squad YAML values, and `supported` plus a safe reason when Squad cannot encode that choice. It excludes machine locations, environment, endpoints, tokens and proxy values; `target_id`/agents bind it to the resolved context. Reusing it in another context requires a new discovery. Unknown provider defaults are left unknown. The caller explicitly decides among backend/provider alternatives.

`parameters` describes only returned choice data: native name, returned values/default, and optional `squad_option` when the adapter really forwards that option. Canonical `reasoning` can additionally preserve its native name and known values/default. Input modalities and context window are informational, not invented execution knobs. A Kimi effort or OpenCode variant may be visible with no `squad_option`; do not pretend `options.reasoning` works there. No pricing or capability guesses from model names. Backend composite identifiers remain opaque: split OpenCode provider/model only at the first slash, preserve the rest, and preserve exact Cursor parameterized IDs.

Deduplicate rows only within one target by provider_id, model_id and selection identity (including alias/opaque model string). Two Kimi aliases for one native ID remain two selectable records. Duplicate equal rows combine provenance. Conflicting metadata for the same identity produces a diagnostic and `partial`, with conflicting optional fields unset; don't choose according to arrival order. Sort targets by backend/origin, rows by provider/model/alias/selection, and source/diagnostic/parameter maps deterministically. Times may differ; semantic ordering must not.

Exit 0 requires every selected target to be complete `ok`/`empty`; exit 1 represents any degraded target, including mixed success and total discovery failure. Exit 2 is CLI/configuration misuse before probing, with JSON `{ "schema_version": 1, "generated_at": "<RFC3339 UTC>", "status": "failed", "results": [], "error": { "code": "invalid_arguments|invalid_configuration|no_targets", "message": "<safe fixed diagnostic>" } }`. The code is one of those exact values; no raw option/config value is interpolated. Successful or backend-result envelopes omit error. Cancellation emits collected results if stdout remains writable and returns 130; whole-operation timeout returns 1. Backend errors must not trigger the current main function's generic usage dump.

Human output is the default without --json. Use deterministic target blocks in the same order as JSON: backend/target/agents, status and completeness, safe diagnostic codes/messages, then exact provider/model/alias and returned display name, executable selection options, known reasoning/defaults, source retrieval/freshness and hidden policy. Show unknown evidence explicitly and unsupported selections as such; print failed/empty targets even without model rows. End with aggregate status and the reminder that inference was not checked. Escape terminal controls in all user/backend strings, do not silently truncate IDs/options, and do not hide partial errors behind successful rows. Human format is readable text, not a parsing API; exact spacing is not contractual.

Exit 1 deliberately combines partial and failed; scripts must inspect JSON status/results to distinguish them. While ZCode has no verified bridge, --all returns 1 even when every other backend succeeds; missing optional tools can also cause this. Do not teach `models --all --json && consume`. Documentation must show capturing 0/1 and inspecting the report, e.g.:

```sh
rc=0
agent-debug-squad models --all --json > models.json || rc=$?
case "$rc" in
  0|1) jq '{status, results}' models.json ;;
  *) exit "$rc" ;;
esac
```

This does not turn exit 1 into success: callers inspect per-target failures before deciding how to proceed, or explicitly filter the desired backend. It is not guaranteed that --all always fails: verified future ZCode support can remove that particular cause.

Readiness/install classification (preserve sanitized phase/code and restart_required in diagnostics; use typed evidence, never parse arbitrary error strings):

| Evidence | Discovery status before any usable rows |
| --- | --- |
| not_found | not_installed |
| unsupported_launcher/runtime/platform; service_incompatible | unsupported |
| not_executable, not_readable, invalid_search_path, check_failed | error |
| start_failed, restart_required, latched managed failure | error |
| timed_out or an expired operation context | timeout |
| cancelled or cancelled caller context | cancelled |
| service_unavailable with confirmed DNS/connect/transport failure | offline |
| explicit authentication-required response, including recognized HTTP 401 | auth_required |
| service_unavailable without a typed cause; generic non-2xx including ambiguous 403 | error |
| snapshot-policy mismatch | error |

The current external ReadinessCheck collapses transport and non-2xx to service_unavailable, so absent richer typed evidence its mapping is error, not guessed offline/auth_required. Classify the caller context before coarse codes. If usable rows already exist, these failures yield partial with the original cause diagnostic. Readiness success never supplies inference evidence; no automatic managed restart follows a latched failure.

### 5. Adapter protocols and lifecycle

**Codex:** spawn the resolved executable in the effective workspace/env, initialize the stdio protocol, acknowledge initialized, and request model/list pages until nextCursor is absent. Pass includeHidden explicitly; default false. Use the returned `model` as the executable selection and preserve `id` separately if different. Never start/resume a thread or send a turn. Recognize notifications without confusing them for replies. Detect repeated cursors and malformed frames; preserve previous valid pages as partial. Map reasoning to existing `options.reasoning`. Missing modality/default fields stay unknown even where UI documentation suggests a compatibility default: this catalog reports evidence. Close stdin, terminate and reap the private process after discovery; never attach to or stop a desktop-owned server.

**Cursor:** invoke only --list-models, with no prompt/print/agent action and noninteractive stdin. Bound and strip known ANSI framing; parse the tested complete document, not arbitrary lines containing a dash. Preserve IDs exactly, including bracketed parameters. A success exit with an unknown format is unsupported, not empty. Empty is permitted only with recognized explicit empty framing. Account-list success establishes listed evidence, not per-provider connected=true or inference success. New structured output can be used only after a capability check and fixture verifies it; --output-format is not such a check.

**OpenCode:** borrow the command-owned Runtime and its existing transport; construct it through NewRuntime/Runtime.Adapter without an orchestrator. Managed mode starts/reuses only that owner's server using the same proxy/snapshot/environment plan and closes the command-owned Runtime after the command; external mode uses exactly its configured endpoint and credentials, bypasses proxies, disables redirects, and never probes a local executable or substitutes another server. Send the workspace directory header used by the execution adapter. GET /provider supplies the known catalog and connected IDs; GET /config/providers supplies configured provider/model membership and defaults. Merge by provider/model, retain all alternatives and distinguish configured/connected. Missing one route with a usable other route gives partial and unknown evidence where necessary. Unknown/malformed classic schema is unsupported; do not combine v1 and v2 formats heuristically. Do not expose provider env/key/options blobs. No session APIs, prompts or config PATCH. The managed lifecycle's snapshot checks remain its responsibility even though discovery itself sends no prompt.

**Kimi:** execute provider list --json with the same cwd/env as actual invocation. Decode only the models map and referenced provider IDs; allowlist documented/observed model fields, bound strings/arrays, and discard arbitrary provider configuration and unknown fields in memory. Keys of models are aliases; native provider/model fields are independent. Mark configured from the local record and connected unknown. Pass the alias unchanged as options.model and fix Send to supply --model when explicitly set; omission retains existing CLI default. Preserve returned effort metadata without mapping it to an unverified CLI option. An older executable without provider list --json returns unsupported; no migration/login fallback. Compatibility of the installed Kimi 2.x run-stream protocol beyond this narrow fix is not certified by model discovery.

**ZCode:** do not call existing host main for discovery: it reads account credentials, bootstraps account state, and starts app-server for conversation use. Static tracing identified createModelCatalogPort -> registry.getView() and a registry runtime factory that starts services and reads selection repositories; invoking it is not yet proven read-only. Absence of string literals model/list or models/list in the inspected bundle is not proof of all future interfaces. Add a separate structurally gated discovery mode only after isolated fixtures establish its startup/write/cleanup behavior. It must not create/resume a session, call the native ListModels agent tool, probe connectivity, migrate config, or persist account overrides. Required structures must be unique before compilation/native credential access, as in the existing bridge compatibility policy. If safe initialization cannot be demonstrated, implement the lister as unsupported with `read_only_catalog_unavailable`; this is a supported outcome, not a blocker requiring speculative code. Static provider-file model lists and old session diagnostics are not substitutes for the effective registry. A verified path returns only normalized registry metadata with account state unknown unless evidenced. Choices outside Squad's current provider/reasoning execution support are retained with selection.supported=false. No exact hash allowlist or promised public endpoint.

### 6. Bounds, freshness and security

At most three target operations run concurrently. Let N be the number of deduplicated targets (positive) and B the --backend-timeout (default 30s). When --timeout is omitted, compute D = max(60s, ceil(N/3) * (B + 5s) + 5s), using checked duration arithmetic. The per-wave allowance covers cleanup/scheduling overhead; the final 5s is dispatch margin. Thus --all with five targets defaults to 75s, seven targets to 110s, and a custom B changes D. This provides headroom, not a promise that slow sources succeed. Overflow is invalid_arguments before probing.

The overall discovery deadline starts after configuration resolution/deduplication, immediately before queuing probes; it includes all queue time. A target's B starts only when a worker takes it, and includes installation, startup, all pages and parsing. Use the earlier of target and overall deadlines. An explicit --timeout replaces D even when shorter than B; accept it and report unfinished targets as timeout, never silently extend it. Configuration parsing precedes this discovery budget and is not claimed to be interruptible filesystem I/O. Cancellation stops queued probes, cancels HTTP/stdio operations, marks uncompleted results, and preserves completed targets. Allow at most five additional seconds solely for owned process-group TERM/KILL/reap cleanup; cleanup failures are explicit errors. Close only command-owned runtimes/processes so external or other users' processes are never killed; bounded cleanup holds its worker slot and is covered by the per-wave allowance when the overall deadline has not expired. No discovery locks span network I/O in the execution orchestrator.

Limit individual protocol frames/responses to 8 MiB, total decoded source bytes to 32 MiB per target, and enumeration to 100 pages/10,000 rows per target. Repeated cursor, budget exhaustion or truncation is partial if rows exist, otherwise error with a limit/protocol diagnostic. Do not claim complete after stopping at a limit. Child stdout/stderr readers are bounded, all goroutines/processes joined, and disconnected upstreams cannot wait forever.

No persistent or cross-invocation Squad cache in v1. Fresh CLI calls are the explicit refresh action; no redundant --refresh flag is introduced. Do not run OpenCode models --refresh, because it refreshes a different CLI catalog and may affect unrelated configuration. Backend-owned caches may still exist: retain explicit stale/as_of/cache evidence, otherwise freshness=unknown. A recent retrieved_at never upgrades unknown upstream freshness to fresh. On source failure there is no silent stale fallback. A future cache needs an independent account/config invalidation contract before introduction.

Only projected model metadata crosses the adapter boundary. Never retain raw Kimi/OpenCode configuration, protocol streams, response bodies, stderr, auth tokens, or request headers as catalog artifacts, even at trace log level. Error messages use fixed templates and safe codes, no raw error interpolation. Redact known credentials, proxy URLs (including encoded forms), URL userinfo/query and credential-bearing text from even allowlisted free-text metadata; clip or omit unsafe values. Treat incoming labels/IDs as data, not shell code: use argument arrays, sanitize terminal control characters for human output, and reject unsafe control characters in executable selections. If an identifier itself is unsafe or secret-bearing, omit that row and mark the result partial/error instead of returning a redacted, incorrect runnable ID. Output does not expose environment fingerprints or endpoint credentials. Do not install/update tools, change native configuration/login, or invoke inference for discovery. Backend-owned incidental caches from documented list commands are not promised absent, but Squad never deliberately mutates auth/config.

### 7. Authoring integration and REST decision

Update `skills/agent-debug-squad/SKILL.md` and README to discover before writing agents/workflow YAML, inspect nonzero-exit JSON, preserve user-specified models, and ask the user to choose when more than one backend/provider fits. An example can show the observed Astra record translated to codex + options.model=gpt-6-astra and a returned reasoning choice; it must be labelled illustrative, not a static lookup table. Unknown explicit models remain pass-through and catalog failures never become model-validation or auth gates.

Do not add GET /models yet: the current API requires a configured squad and owns a startup machine-settings snapshot, while this feature's essential use is before that squad exists. A future route can reuse the service with the server's own snapshot/runtime owner and request cancellation; arbitrary remote workspace/credential overrides would require a separate contract. Deferring it avoids hidden process ownership and configuration divergence.

## Risks / Trade-offs

- [Catalog scope is weaker than access] -> independent evidence fields and universal not_checked inference status; no trial inference.
- [Cursor output and private ZCode structures drift] -> shape/structure checks, version-labelled fixtures, partial/unsupported results, no empty-success fallback.
- [Native bootstrap has hidden writes] -> ZCode defaults to unsupported until isolated write-denial tests establish the dedicated bridge path; no session workaround.
- [Constrained environment cannot find a logged-in account] -> reuse execution semantics and explain which setting category to inspect rather than inherit everything.
- [No Squad cache means repeat discovery cost] -> bounded parallelism and single-pass deduplication; correctness and account isolation outweigh cache complexity for a one-shot CLI.
- [Planning worktree predates merged dependencies] -> update the implementation base to main containing eedfa95 and 88ec978 before coding; use the actual Runtime/check APIs above rather than an assumed lease API.

## Migration Plan

Before implementation, update the code base to main containing the already merged managed OpenCode and installation-check commits while preserving these planning files; no alternative interface-extraction branch is planned. Add discovery behind the new CLI, update authoring documentation, and retain existing run/HTTP/snapshot behavior. The only execution correction here is forwarding explicitly configured Kimi model aliases; document it and test exact argv. This is a compatibility change for configurations with stale, misspelled or placeholder Kimi options.model: those values were previously ignored and will now reach the CLI and may fail. Users must replace them with a returned configured alias or remove options.model to retain the native default; do not automatically rewrite YAML or fall back after a rejection. Rollback removes the new command and documentation; no stored catalog or workflow migration is required. No release tag is part of this change.
