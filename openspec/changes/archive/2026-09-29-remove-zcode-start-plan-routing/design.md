## Context

The plan-routing apparatus landed as one unit in `c567ad6` (v0.19.0): `planpolicy.go`, `routing.go`, `evidence.go`, `continuation.go`, `hostbridge.go`, the guarded-read half of `host.cjs`, and the routing call sites in `zcode.go`. The pre-change adapter dispatched with: exactly one Individual credential key resolved at bootstrap, a host-side overlay marking that provider entitled/current against the real native registry revision, and `session/create`/`resume` with the configured selection — no network read against Z.AI origins before dispatch. The current `Send` flow is: bootstrap (`planPolicy` param, JWT load for start-first) → wire probes → routing decision (`decideFixed`/`decideStartFirst`, the failure site in the PR-651 bundle: the subscription-list GET inside `decideIndividual`) → `squad/applyAccountOverlay` with the decision verdict → session create/resume. Files that are plan-routing-only and have no other callers: `planpolicy.go`, `routing.go`, `continuation.go`, `testdata/billing/*`, and the subscription-list fixtures. `evidence.go` and `hostbridge.go` are half plan-routing (billing/subscription decoders, HTTP readers) and half the retained local selectability check (registry-view decode and bridge); `testdata/registry/registry-view.json` serves that check and stays.

## Goals / Non-Goals

Goals: remove the Start Plan surface, its diagnostics, and the active-subscription gate (the pre-dispatch network dependency that broke the PR-651 run), while keeping the rest of the hardening — including the local registry-view selectability preflight.

Non-Goals: no removal of the local model/reasoning selectability check, wire compatibility probes, reverse-request servicing, background-work tracking/cleanup, safe stderr provenance, redaction, or permission scoping; no new provider paths; no changes to other backends; no migration tooling beyond a clear validation error.

## Decisions

- **Reject `plan_policy` loudly instead of ignoring it.** `internal/config/zcode.go` and adapter `Init` fail with "plan_policy was removed; remove it from the agent options". Silently ignoring would let a stale v0.19 config that requested start-first run Individual-only without the user noticing. Alternative considered: accept `fixed` as a no-op — rejected because it keeps a dead option alive in docs and examples.
- **Keep the Go-driven overlay RPC, drop the routing verdict.** `Send` still calls `squad/applyAccountOverlay` after bootstrap, but unconditionally with the configured Individual provider and entitled/current set. This preserves the current host contract (host attaches the real native revision, guards the provider family) with the smallest diff; pre-harden pushed the same overlay from the host at bootstrap, which would be a second valid shape but rewrites more of the host wire. The host's provider-family check shrinks to the Individual ID.
- **Keep the auth-binding reverse request; collapse the Start branches.** `interaction/requestProviderRuntimeHeaders` keeps routing through the Go round-trip (`squad/authorizeProviderHeaders`) with generation/workspace/turn scoping — that is credential safety, not plan routing. The `captcha-retry`/Start-provider special case is deleted; any non-Individual or non-`model-request` challenge falls into the existing unsupported-interaction failure, matching pre-harden behavior.
- **Keep the local selectability preflight, drop only its network prerequisite.** The registry-view check (exact provider/model/reasoning selectable after applying the account evidence) is local to the installed bundle, cannot cause the PR-651 failure class, and catches misconfigured model/reasoning selections before dispatch — it stays, reissued as a direct pre-dispatch verification instead of the tail of a routing decision. The subscription-list GET that preceded it is the removed part. Alternative considered: full pre-harden dispatch parity (no check at all) — rejected: it trades a useful local gate for nothing and widens the revert beyond the requested scope.
- **Bootstrap drops the `planPolicy` param and JWT load entirely.** Identity resolution returns to the fixed rule (exactly one Individual key); `resolveIdentity`, JWT decoding, `authMaterial`, and the `hasStart`/`identityMatch` bootstrap fields are removed along with the `squad/readStartBalance` / `squad/readIndividualSubscription` handlers and `performRead`/`requestViaProxy`/app-version machinery that only served the network reads. `squad/readRegistryView` and its bundle dependencies (registry factory, snapshot parser, `syncAccountProviderConfig`) stay. `ZCODE_HTTP_PROXY`/`ZCODE_NO_PROXY`/`ZCODE_AGENT_CA_CERT` env injection is unaffected — the runtime's own network stack consumes those; only the adapter's own HTTPS client disappears.
- **Restore `selection()` to the configured provider.** `session/create` model selection uses the agent's `provider` option (Individual-only after validation) instead of `decision.Provider`; `activeRun` drops the provider/decision fields.
- **Tests and fixtures follow the code.** Delete routing/continuation/planpolicy tests, the billing/subscription evidence tests, and their fixtures; keep the registry-view contract tests and `testdata/registry/registry-view.json` for the selectability preflight; keep wire-probe fixtures (drop the quota-exhaustion frame from `legacy-wire.json` if it is only used by continuation tests); keep contract tests for bootstrap identity, overlay family guard, auth-binding scoping, and the new `plan_policy` rejection.

## Risks / Trade-offs

- [Users on v0.19.0 with `plan_policy: fixed` hit a validation error after upgrade] → the error names the option and the fix is deleting one line; README migration note included.
- [Losing the active-subscription gate means a stale or absent subscription now surfaces as a turn failure after dispatch instead of a pre-dispatch routing failure] → accepted: the turn failure still carries a safe error, and the gate's cost (a hard dependency on `api.z.ai` before every run) is what broke the PR-651 review.
- [The retained registry-view preflight depends on bundle structures beyond the wire probes (snapshot parser, `syncAccountProviderConfig`, `getView`), so a desktop update that breaks them fails runs pre-dispatch] → same fail-closed philosophy as the wire probes; the structures were pinned from the inspected upstream source and are covered by contract tests, and drift surfaces as an actionable "update the adapter" error rather than a hang.
- [Deleting the guarded-read TLS/proxy client removes reviewed code that could be useful later] → it stays in git history and the archived `harden-zcode-source-contracts` change; resurrecting it later is a revert away.

## Migration Plan

1. Land the change on `main` behind normal review; no persisted state references routing diagnostics or `plan_policy`, so no store migration is needed.
2. Users remove `plan_policy` (and any `account:zai-start-plan` provider) from squad YAML; the validation error guides this if forgotten.
3. Rollback = revert the commit; the option becomes accepted again with v0.19.0 semantics.
