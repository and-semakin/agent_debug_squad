# ZCode source investigation

## Evidence and reproducibility

Reviewed 2026-09-28. A clean existing temporary checkout was inspected read-only. `git rev-parse HEAD` and remote `git ls-remote` agreed on `29628c9acdb81b703bbd4080c207a0e7ce5e276e`; remote `main` and peeled annotated `v3.14.3` point there (tag object `7e7bd174e29b622a8080e0acf738b74a933a27ae`). The locally installed app's non-secret Info.plist reports 3.14.3; that does **not** prove its bundled bytes equal this source commit.

Evidence classes below: **S** = inspected source; **L** = read-only local metadata; **P** = runtime protocol observation; **I** = inference/design. There are **no P observations in this investigation**. No real credential/configuration contents, account state or transcripts were read; no inference, session creation, runtime launch, setup/build scripts, login, update or account writes occurred. Protocol startup opens/migrates SQLite, prepares provider caches and telemetry, so it would not be honest to call an ordinary launch a read-only probe. An isolated synthetic no-network integration harness belongs to implementation validation, not a fabricated successful result here. Source tracing resolved the architectural blocker without a build.

## Entry points, packaging and compatibility

**S:** [CLI dispatch](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/apps/zcode-cli/packages/cli/src/run.ts#L236) routes both `app-server` and `agent-server` to the same protocol function; the adjacent comment explicitly describes packaged app-server as the desktop host's internal subprocess. Renaming the command to agent-server does not enable standalone auth.

**S:** [CLI manifest](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/apps/zcode-cli/packages/cli/package.json) exposes `dist/zcode.cjs`; [build script](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/apps/zcode-cli/packages/cli/scripts/build.mjs) bundles the CLI, with distribution-specific external resources. The [upstream README](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/README.en.md) describes the unified CLI/TUI/Web distribution without Electron. A CJS CLI can be run using Node and `app-server`; this is an implemented internal interface, not a stability promise for third-party clients. Source packages are private workspace packages, not evidence of an installable supported SDK. Copying `@zcode/bootstrap` imports into a host would pull its workspace graph and packaging burden.

**S:** [protocol schema](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/packages/shared/src/zcode-protocol/index.ts#L74) names `ZCODE_PROTOCOL_VERSION = 1`. The desktop's major version 3 and the historical description “v3 protocol” must not be sent as wire version 3. [v4](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/packages/shared/src/zcode-protocol-v4/transport.ts) has hello/clientHello, topic subscriptions, ACK/frames, sequence/log epochs and capability bits for a different transport boundary. [Server dispatch](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/apps/zcode-cli/packages/bootstrap/src/zcode-protocol/server.ts#L457) serves both legacy session operations and v4 gateway operations. No general initialize/negotiated method inventory for the legacy NDJSON client was found. `runtime/capabilities` currently returns only `{independentPlanState:true}`. MCP `protocolVersion` fields in this file negotiate MCP and are unrelated.

**I:** Keep legacy `session/*` as an explicitly tested dialect; never infer v4 compatibility from that single capability. Behavioral validation, bounded invalid-parameter method probes where parsing precedes side effects, and schema fixtures are better than hashes for native mode. They still cannot establish every future runtime semantic before a turn: validate each subsequent boundary and report drift. Legacy extraction must retain its separate structural guard while extraction remains.

## Actual authentication path

**S:** [protocol entrypoint](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/apps/zcode-cli/packages/bootstrap/src/zcode-protocol-entrypoint.ts#L145) calls `startProcessProviderRegistryRuntime(runtimeEnv)` **without** its second `standalone` option. [Registry creation](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/apps/zcode-cli/packages/bootstrap/src/app/process-provider-registry-runtime.ts) creates a credential store and standalone account service only with that option; otherwise it creates a mutable account source for host overlays. [Workspace runtime](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/apps/zcode-cli/packages/bootstrap/src/zcode-protocol/workspace-model-runtime.ts#L69) supplies the reverse-RPC provider auth port. The protocol entrypoint does not expose a CLI flag that injects the standalone port. [Prompt CLI](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/apps/zcode-cli/packages/cli/src/prompt-command.ts) and [TUI runtime](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/apps/zcode-cli/packages/cli/src/tui-prompt-handler-runtime.ts) explicitly opt into standalone; their existence is not evidence for app-server parity.

**S:** [Standalone account code](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/apps/zcode-cli/packages/bootstrap/src/app/standalone-account-provider-runtime.ts) looks up a per-provider identity marker, then that identity's key; missing identity/key yields entitled=false. Its “refresh” hook rereads credentials before each model request, not an OAuth token refresh implementation. It supports configured individual plans by family; it does not reproduce desktop Start/Team selection.

**S:** [Shared credentials](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/apps/zcode-cli/packages/adapters/src/auth/shared-credentials.ts) owns private key names and storage location; [cipher](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/apps/zcode-cli/packages/adapters/src/auth/credential-cipher.ts) implements enc:v1, AES-GCM, configured-secret or OS-derived fallback. These are inspectable private formats, not an invitation to reimplement them in Go. Source availability alone does not make copied decryption safer or compatible with future installations.

**S:** The real desktop service [responds to provider auth requests](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/packages/services/src/zcode-agent/zcodeAgentService.ts#L1258) through `accountRequestAuthService.resolveCurrent`. [Auth resolver](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/packages/services/src/model-provider/accountProviderRequestAuthService.ts) distinguishes Start JWT, Individual API key and Team request key. [Connection resolver](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/packages/services/src/model-provider/accountProviderConnectionResolver.ts) considers selected family/mode, account identity, Team scope and concurrent identity changes; `current` is not equivalent to “one credential key exists.” Entitlement/current/refresh are host service responsibilities. Recreating this service graph or invoking login/refresh from Squad is out of scope.

**S:** [Reverse headers port](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/apps/zcode-cli/packages/bootstrap/src/zcode-protocol/provider-runtime-headers.ts) assigns a unique request ID, has a 180-second total timeout, and emits `interaction/providerRuntimeHeadersCancelled` through the named notification constant on cancellation/timeout. The notification string is confirmed by the protocol notification table (line 337 at this commit). The wire request reason at this commit is only `model-request`; wider service reasons are not additional wire capabilities. Responses carry request-local auth material. [Account config update](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/apps/zcode-cli/packages/bootstrap/src/zcode-protocol/account-provider-config.ts) accepts a host overlay, returns received/unchanged, and must not be confused with proof that a selected model is executable.

**I:** Native personal API execution can leave provider secrets under the runtime's own config handling. Current Coding Plan execution cannot drop both credential access and overlay merely by switching commands. Retain the narrow legacy path rather than silently turn account credentials into personal API config, copy the cipher, or invent an undocumented desktop IPC auth broker. This change deliberately does not claim current-account support beyond the existing restricted legacy profile. Multiple stored identities remain unsupported; account rotation must invalidate the run or be reread under that exact identity, never select a different key.

## Catalog: internal port is not an external endpoint

**S:** [ModelCatalogPort](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/apps/zcode-cli/packages/contracts/src/interfaces/model-catalog.port.ts) defines providerId, modelId, providerLabel, reasoningLevels, defaultReasoningLevel, contextWindow, current and disabledReason. [Port implementation](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/apps/zcode-cli/packages/bootstrap/src/app/model-catalog-port.ts) reads the current registry view on each call. This is an in-process tool/runtime port. `ListModels` is an agent tool, not a free external CLI model-list operation.

**S:** The protocol method dispatch has no `model/list` equivalent. [Session mapper](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/apps/zcode-cli/packages/bootstrap/src/zcode-protocol/session-mapper.ts#L219) can map app models but callers can restrict it to current selection. [Workspace presentation](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/apps/zcode-cli/packages/bootstrap/src/zcode-protocol/workspace-model-runtime.ts) returns mode/slash commands; [v4 workspace projection](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/apps/zcode-cli/packages/bootstrap/src/zcode-protocol/v4-workspace-config.ts) explicitly leaves model candidates to Host ModelSelectionView. Type fields capable of representing model options do not prove the endpoint supplies them.

**S:** [Built-in source read](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/packages/provider-node/src/zcode-builtin-provider-config-source.ts) may materialize active state; [personal repository read](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/packages/provider-node/src/personal-provider-config-repository.ts) has recovery/import/watch behavior. “Read registry” is not proof of a configuration-read-only initialization path. The built-in source revision combines release revision and source identity, so replacing registry extraction with the JSON numeric revision would be incorrect.

**I:** Keep the catalog adapter's explicit unsupported result for both integrations at this baseline. Do not start Web/Electron or construct a second host merely to gain a model facade. A future upstream session-free read-only catalog endpoint would be a bounded follow-up, preserving the common catalog's metadata/limits rather than another CLI/API.

## Lifecycle and environment findings

**S:** [NDJSON transport](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/apps/zcode-cli/packages/bootstrap/src/zcode-protocol/transport.ts) routes reverse responses outside the ordinary request queue and lets stop/cancel controls bypass long handlers after ordering barriers. It drains EOF for 100 ms. Squad must service callbacks while create/resume or another RPC is outstanding; processing callbacks only after send is insufficient once host responsibilities move into Go.

**S:** [Session operations](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/apps/zcode-cli/packages/bootstrap/src/zcode-protocol/server-operations.ts) distinguish accepted send from later turn completion. `session/stop` aborts an active prompt and may pause a goal; `session/cancelBackgroundTask` is separate; `session/close` closes the resident app and removes its in-memory record, not the persisted conversation. A stop acknowledgement does not establish that detached work has gone. [Background owner lookup](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/apps/zcode-cli/packages/bootstrap/src/zcode-protocol/background-work-owner.ts) walks ancestors for the live executor. [Runtime cleanup](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/apps/zcode-cli/packages/bootstrap/src/zcode-protocol/runtime-cleanup.ts) uses a shared 1.2-second budget and independently attempts resource disposal; it does not eliminate the need for Squad's process-group fallback.

**S:** [CLI env](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/apps/zcode-cli/packages/cli/src/env.ts) sanitizes runtime/tool environment and only loads workspace dotenv in development protocol mode. [Provider environment](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/apps/zcode-cli/packages/cli/src/provider-runtime-env.ts) honors explicit built-in/personal paths, `ZCODE_DATA_BASE_DIR`, SEA assets and real entrypoint location. CLI CJS and desktop config layouts differ. Supplying both explicit config paths bypasses automatic preparation. Data base, session storage and encryption identity are distinct concepts. No bridge should assume changing HOME and changing data base are interchangeable.

**S, local repository:** `host.cjs` currently hardcodes the Z.AI provider and `.zcode/v2` below HOME, reads legacy cache availability, requires exactly one matching key, decrypts once, and hardcodes entitled/current. It owns callbacks without session/turn ownership checks. `zcode.go` already preserves IDs, sends full selection on every turn, requires owned completion with nonempty response, and kills its owned process group. Gaps worth fixing include callback servicing during synchronous calls, stale final events, unbounded descendant pagination/tree work, coarse errors, raw runtime stderr exposure, and treating stop/close as adequate background cleanup. Existing tests cover useful lifecycle/permissions/cancellation cases but use a handcrafted protocol helper; they do not establish compatibility with the published runtime.

## Comparison and decision

| Approach | What it removes | What remains / why not universal |
|---|---|---|
| Direct CJS `app-server` + Go client | All bundle regex/eval/thunks and Squad account-secret handling for personal API providers | Internal wire contract; runtime owns config; account auth remains a missing host responsibility |
| Minimal Go host policy + isolated legacy auth shim (selected) | Common host logic leaves JS; native path needs no JS bridge; legacy auth scope becomes explicit | Existing account path still uses guarded extraction/overlay; not a claim to eliminate its fragility |
| Import bootstrap/standalone runtime into custom TS host | Could replace minified-name discovery | Private workspace packages, separate account semantics, changed runtime assembly, distribution graph; effectively a maintained runtime integration/fork |
| Copy credential cipher + registry/account rules | Regex could disappear for one file format | Squad owns another credential and entitlement implementation, does not obtain native refresh/current-account semantics |
| Switch everything to prompt/TUI | Gains standalone individual credential handling | Loses the current persistent session/permission/control contract; not a drop-in replacement |
| Assume v4 or Web host solves auth/catalog | None established | Different host/service and transport boundaries, initialization side effects; no verified stable external broker |

The selected hybrid makes a real bridge-free path available while preserving existing users. Removing the remaining account shim requires a verified upstream protocol-server standalone-account option or external native host auth/catalog contract; neither is demonstrated at this commit. This is a documented limitation, not an implementation task to discover an unspecified architecture.


## Authorized installed-account verification — 2026-09-28

The user explicitly authorized short real-account conversations and code fixes. Installed ZCode Desktop reports 3.14.3. Evidence below is limited to the tested installation; no credentials, billing records, device identifiers, or CAPTCHA tokens are recorded.

- Fixed Individual GLM-5.3-Flash: `pong`, then `4` in the same native session, confirmed twice.
- Start balance: initially HTTP 400. Mirroring `services/providers/sourceHeaders.ts` and `api/nodeApiClient.ts`, including the existing device header, makes the guarded balance read succeed. Device identity is read, never generated or changed.
- Start-first GLM-5.3: `routing_start_model_absent` selected Individual on both turns; replies were `pong` and `4` with the same native session.
- Start-first GLM-5.3-Flash: routing selects `account:zai-start-plan` with `routing_start_available`. Model execution then requests `captcha-retry`; it is rejected without Individual fallback.
- The installed bundle differs from the pinned public source: its request-reason enum includes `captcha-retry`. Inspection of the installed Desktop renderer shows Start requests obtaining CAPTCHA verification material per request. The pinned public source only declares `model-request`. Ordinary JWT auth and successful balance access are insufficient to claim Start inference support. A supported human-verification/Desktop bridge is still required; CAPTCHA verification is not bypassed, fabricated, or replayed.
- Startup/state/computer-use notifications no longer fail ordinary turns. Unknown reverse *requests* remain unsupported; storage initialization failure remains fatal.
- Regression tests cover notification dispatch, storage failure, billing URL/auth/source headers and reuse (without creation) of the existing device identity. `TestLiveZCodePlanRouting` is explicitly opt-in and records routing decisions and short replies only.

No offer activation, reset redemption, subscription change, release or personal API mode was used. Quota exhaustion was not forced. Installed isolated lifecycle harness and full Start compatibility remain open tasks.
