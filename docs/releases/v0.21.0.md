# v0.21.0 — local Devin ACP backend

Release notes for the local Devin ACP backend.

## Changes

- Add `backend: devin` for Cognition's official local CLI over ACP v1, including persistent manual conversations, fresh workflow attempts, explicit model selection, permission replies and bounded cancellation/cleanup.
- Require an explicit model and add checked reasoning, speed and mode selections. Defaults are high reasoning when offered, standard speed and bypass mode; explicit mode overrides implicit yolo.
- Add machine-level Devin executable, proxy and environment settings, installation preflight and session-free model discovery. Catalog variants without verified ACP encodings remain informational.
- Stop dispatch when saving an allocated backend session fails. Release retained native preparation on cancellation, expiry or pre-dispatch failure.
- Make the paused-loop recovery test use one deterministic scheduler, avoiding spurious preflight conflicts from competing background and manual reconciliation.
- Document the supported native profile and add a configuration example, subprocess regression tests and an opt-in live continuity test.

## Compatibility and limitations

Verified on macOS with Devin CLI `3000.11.1 (cc4e349ca55e)` using explicitly inherited proxies. Small live sessions checked inference, continuation, file tools, permission decisions and cancellation. Native Linux inference has not been checked.

The tested CLI offers no Normal ACP permission mode. `yolo: false` without an explicit mode fails before prompting. Explicit `mode: accept-edits`, `ask`, `plan`, `smart` and `bypass` are checked against the session's advertised choices. Neither mode nor yolo establishes an OS sandbox. Fast is model-specific; unsupported explicit controls fail before prompting.

Hooks, MCP and plugins are outside the initial supported profile. Native user/project configuration is not rewritten; unsupported profiles fail before launch. Authentication stays an operator action, and native inference consumes the account's quota. Exact model IDs are checked against live ACP controls; catalog variants are not guaranteed to be selectable.

Existing non-Devin configurations do not require migration. Devin agents must now specify `options.model`; use an exact ACP selection ID. `models --all` now also probes Devin, so an unavailable Devin installation can produce a partial result and exit 1 alongside successful backends.

## Validation

Required checks: repository formatting, `git diff --check`, `go vet ./...`, `go test -race -count=1 ./...`, `go build ./...`, strict OpenSpec change/spec validation, and CI on the pushed commit. Release preparation also cross-compiles the four supported targets and runs the opt-in native continuity smoke test.

## Publishing

The new backend warrants the next minor version, `v0.21.0`, after `v0.20.0`. Versions remain Git-tag-derived; the embedded development version is unchanged.

1. Merge the reviewed implementation into `main`, check that the release commit has green CI, and verify a clean checkout.
2. After explicit publication authorization, create the annotated tag with `git tag -a v0.21.0 -m "v0.21.0"` on that commit and push it.
3. Watch the **Release** workflow finish successfully.
4. Verify `checksums.txt` and all four archives: `agent-debug-squad_darwin_amd64.tar.gz`, `agent-debug-squad_darwin_arm64.tar.gz`, `agent-debug-squad_linux_amd64.tar.gz`, and `agent-debug-squad_linux_arm64.tar.gz`.
5. Verify the downloaded native binary reports version `v0.21.0` (or GoReleaser's normalized `0.21.0`), the tagged commit, and a build date.
