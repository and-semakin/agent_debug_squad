# v0.21.1 — ZCode account revision fix

## Changes

- Fix ZCode startup failing with `The registry view could not be materialized; update the adapter.` before a conversation is created. Account snapshots and App Server overlays now send the native case-sensitive `basedOnZCodeBuiltinRevision` field instead of `basedOnZcodeBuiltinRevision`.
- Add a hermetic test of the actual JavaScript host covering registry projection, App Server overlay receipt, and rejection paths without real credentials or model requests.

## Compatibility

Existing YAML and persisted state need no migration. Update Squad, restart the running Squad process, and retry the failed work explicitly.

The field mismatch was reproduced against the local ZCode 3.14.4 parser and independently confirmed by static inspection of a reported ZCode 3.15.3 bundle. That inspection does not certify all 3.15.3 runtime operations.

`agent-debug-squad models --backend zcode` still reports `read_only_catalog_unavailable`: read-only catalog discovery is not implemented. That result does not test the installed runtime or establish that inference is broken.

## Validation

The host regression fails on the previous code and passes with this fix. Release validation includes formatting, `git diff --check`, `go vet ./...`, `go test -race -count=1 ./...`, `go build ./...`, strict OpenSpec validation, and CI on the release commit.

The local opt-in Flash smoke test on ZCode 3.14.4 passed registry verification and account overlay application, created a session and reached inference. It could not complete its two-turn continuity check because Z.AI returned HTTP 429 / provider code 1308 (five-hour account usage limit). Successful inference and remote 3.15.3 live execution are not claimed.
